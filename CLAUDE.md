# GODLister — project state

A Tauri 2 desktop app (Rust backend + plain HTML/CSS/JS frontend, no framework) that scans a chosen folder and writes a `.txt` listing of its contents to a chosen depth. UX is deliberately styled after the user's other project, `iso2god-gui` (github.com/CamiBurger/iso2god-gui): gear-icon Settings panel, first-run setup wizard, settings persisted to JSON, native file dialogs via `tauri_plugin_dialog`.

**Name history**: "Directory Lister" → "GOD Directory Lister" → **"GODLister"** (current, user's choice — wanted something more concise but still unique/informative on macOS, i.e. in the menu bar/Dock). `productName`/window title in `src-tauri/tauri.conf.json` and the frontend both reflect this. The bundle `identifier` (`com.dirlistergui.app`) has been deliberately left unchanged through all renames — it's the settings-storage path key (`~/Library/Application Support/com.dirlistergui.app/settings.json`); changing it would orphan any already-saved settings.json.

**Source**: this directory (`~/Downloads/dir-lister-gui`). **Now a git repo** (initialized 2026-07-31) with GitHub remote `CamiBurger/xbox360-god-directory-lister` (public). Work is being pushed to a `test` branch, not `main`, per user request. `.gitignore` excludes `/src-tauri/target/` (huge, rebuildable), `/src-tauri/gen/schemas/` (Tauri-generated), `.DS_Store`, and `.claude/` (local tooling config, not project source).

**Icon**: custom-designed, not from a template. Dark grey rounded-square background (`#2e2e30`) with a flat green (`#178a49`/`#22a559`) folder-tab + bulleted list glyph — deliberately avoids looking like a word-processor/document icon (an earlier white-page-with-folded-corner design was rejected for looking too "Word doc"), and avoids resembling the user's other app's icon (a macOS litter-cleaning tool). Source SVG was one-off scratch work, not checked into the repo; regenerate via `cargo tauri icon <path-to-1024x1024-png-or-svg>` if it needs revisiting — note ImageMagick's SVG rasterizer (used to go from SVG to PNG for that command) doesn't support gradients (renders black) and doesn't reliably honor `stroke-width` on `<line>`/`<g>` elements — use flat fills and `<rect>`/`<circle>` shapes instead.

**Built app**: `src-tauri/target/release/bundle/macos/GODLister.app` after running `cargo tauri build`. A standalone copy is kept at `~/Downloads/GODLister/GODLister.app` for easy testing — **rebuild and recopy before testing again** if source changed (steps below). (Earlier standalone copy folders — `~/Downloads/Directory Lister/`, then `~/Downloads/GOD Directory Lister/` — were deleted and replaced each time the app was renamed.)

## What's implemented

**Settings** (persisted to `~/Library/Application Support/com.dirlistergui.app/settings.json`):
- `default_depth` (**i32**, default 2). Semantics: `0` = just the header line (selected folder's own path, nothing else). `1` = files and folders directly inside the selected folder. `N` = that many levels deep. `-1` = **no limit — walks the entire tree** (added per user request; UI's number input has `min="-1"`). Listing includes both files and folders.
- `god_recognition` (bool, default false) — labels any folder whose name is exactly 8 hex characters with its game name, looked up in a bundled CSV (`src-tauri/resources/gamelist_xbox360.csv`, sourced from `r4dius/Iso2God`, ~4046 entries, embedded via `include_str!`). No parent-folder restriction.
- `content_type_recognition` (bool, default false, only meaningful when `god_recognition` is also on — UI disables/unchecks it otherwise) — labels known STFS content-type folder codes (`00000002` → DLC, `000B0000` → Title Update, `00007000` → Games on Demand, etc. — full table hardcoded in `content_type_name()` in `main.rs`) found as immediate children of a detected 8-hex-char title-ID folder. **Also**, under this same toggle: individual DLC package files found inside a detected `00000002` (DLC) folder get labeled with their actual DLC name (e.g. `"B11C...58 - Night Missions Map Pack"`), via `build_dlc_title_map()` matching the file's own 42-hex-char name (its STFS content ID) against a bundled catalog.
- `ask_every_time` (bool, default true) — whether Settings opens on every launch or just once.

**Output `.txt` format**: first line is always the absolute path of the scanned root folder (a header). Below that, one line per entry, indented two spaces per depth level.

**Main view**: pick folder to scan → either pick a save location (`.txt`, default name `directory_listing.txt`) **or** check "Just show me the result instead of saving to a file" → Generate List.
- Normal path (output path chosen): writes the file, result area shows counts (entries written, GOD matches, content-type matches).
- **Preview path** (checkbox on, added per user request): nothing is written to disk. `generate_listing` is called with `output_path: null`; the backend returns the full listing text in `content` instead of writing it. Frontend shows it in a full-window popup (`#preview-overlay` / `#preview-modal` in `index.html`) with the text in a `<pre>`, plus "Close (discard)" (just hides the modal — nothing was ever written, so closing is truly deleting it) and "Save As…" (opens the save dialog, then calls a separate `save_text(path, text)` command to write it at that point). This is the "entirely temporary unless you choose to save" behavior the user asked for.

## Key files
- `src-tauri/src/main.rs` — all backend logic: settings persistence, `pick_scan_root`/`pick_output_path`/`generate_listing`/`save_text` Tauri commands, `collect_entries` (recursive walk, `max_depth: Option<u32>` where `None` = infinite), `label_for` (labeling precedence: content-type check → DLC-content-id check → GOD-title check → raw name), `content_type_name()` (hardcoded STFS content-type table), `build_god_title_map()` (parses the bundled Title ID CSV), `build_dlc_title_map()` (parses the bundled DLC-titles CSV).
- `dist/index.html`, `dist/app.js`, `dist/style.css` — frontend, mirrors `iso2god-gui`'s two-view (`setup-view`/`main-view`) pattern, plus the preview modal (`#preview-overlay`).
- `src-tauri/resources/gamelist_xbox360.csv` — bundled Title ID → game name lookup table.
- `src-tauri/resources/dlc_titles.csv` — bundled ContentId → DLC name lookup table, 14,168 rows / ~6,000 unique content IDs after dedup. Originally sourced from the user's own repo, github.com/CamiBurger/xbox360_DLC_titles (which itself scrapes `catalog.xboxlive.com`, replicating XM360's `FindGames`/`FindGameOffers` requests — see that repo's README for regeneration steps if the CSV ever needs updating). It's real RFC4180 CSV (quoted fields, embedded commas, escaped quotes) with **CRLF line endings** and a first line that's just a bare generation-date stamp (not a header row) — parsed with the `csv` crate, not hand-split. Field 5 (0-indexed) is DLC Name, field 6 is ContentId (42 uppercase hex chars — 20-byte hash + a constant `58` suffix byte per the source repo's README — this is literally the on-disk filename of the installed DLC package under a title's `00000002` folder). Many rows share the same ContentId (bundled multi-item packages); first-occurrence-wins on dedup, same convention as `build_god_title_map()`.
  - **Fixed a real bug in the source CSV** (2026-07-31, pushed as commit `099fe95` on `CamiBurger/xbox360_DLC_titles` main): 111 of the 14,168 rows had broken quote-escaping in the DLC Name field — the generator wraps a field in `"..."` whenever it contains a comma, but never doubles literal `"` characters already inside the field (common for song-title DLC names formatted like `"Song Name" - Artist`), so a strict RFC4180 parser either misreads or drops those rows. **First repair attempt was itself buggy** and would've silently corrupted ~7,743 already-correct rows (e.g. turning the perfectly valid, unquoted-with-embedded-quotes `Additional Playable Character "Makoto Nanaya"` into a mangled, character-losing `"Additional Playable Character ""Makoto Nanaya"`) by stripping boundary quote characters unconditionally instead of only from fields the generator had actually wrapped. Caught by diffing the repaired file against the original before pushing — always do that for this kind of bulk text repair. The correct fix only touches a field's boundary quotes **when the field's raw span contains a comma** (the only condition under which the buggy generator ever wraps a field at all, so that's the only case where a boundary quote is a wrapper artifact rather than genuine content) — verified this against every one of the 111 broken rows (e.g. `""Girl, You Have No Faith in Medicine""` → `"Girl, You Have No Faith in Medicine"`) and confirmed the final diff against the original touched **exactly** 111 lines, byte-identical everywhere else. Fixed copy: `~/Desktop/DLC_titles_fixed.csv`, also swapped into this repo's bundled resource. **If the CSV is ever regenerated from the live catalog again, this same escaping bug will likely reappear** — rerun this exact repair (comma-gated boundary-quote strip on only the rows that fail strict parsing, not a blanket pass) rather than re-deriving it from scratch, and diff-check the result before trusting it.
- `src-tauri/icons/` — regenerated via `cargo tauri icon`; see Icon note above before touching these directly.

## Known-fixed bug (worth knowing if similar symptoms recur)

The preview modal's `hidden` attribute was initially overridden by a `.overlay { display: flex; }` CSS class rule of equal specificity that loaded after the browser's UA stylesheet — so `hidden = true` was silently not hiding the modal. Symptom looked like "Close does nothing, and clicking Save afterward errors with `invalid type: null, expected a string`" (because Close *did* clear `state.previewContent` to null even though the modal stayed visible, so a subsequent Save sent null through). Fixed with an explicit `.overlay[hidden] { display: none; }` rule (higher specificity, wins regardless of source order) in `style.css`, plus a defensive null-guard at the top of `saveFromPreview()` in `app.js`. **General lesson for this codebase**: never rely on a bare `hidden` attribute co-existing with a class that sets `display` on the same element without an explicit `[hidden]` override — the class will win.

## Rebuild steps

```
cd ~/Downloads/dir-lister-gui/src-tauri && cargo build   # quick sanity compile
cd ~/Downloads/dir-lister-gui && cargo tauri build        # produces the .app
```

The `.dmg` bundling step has been succeeding in this environment lately (earlier notes said it reliably failed — that seems to no longer be the case, but if `bundle_dmg.sh` does error, it's harmless; the `.app` is what matters). If a stray `/Volumes/dmg.*` volume or `rw.*.dmg` temp file is left behind from that step, eject/remove it (`hdiutil detach /dev/diskN`).

To hand the user a standalone copy: `mkdir -p ~/Downloads/GODLister && cp -R "src-tauri/target/release/bundle/macos/GODLister.app" ~/Downloads/GODLister/`.

## Note on disk space in this environment

Twice this session, the sandbox's disk filled completely (`ENOSPC`, even on plain `~/Downloads` writes, not just scratch space) after a handful of `cargo tauri build` runs plus `.dmg` bundling temp files. Both times the user freed space externally and things resumed fine. If every tool call starts failing with `ENOSPC`, that's almost certainly this recurring issue, not a code problem — ask the user to free space (Trash, or deleting `src-tauri/target/` which rebuilds from scratch) rather than debugging further.
